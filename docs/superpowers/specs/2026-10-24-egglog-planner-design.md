# egglog-planner 首版设计

日期：2026-10-24

## 意图

作为独立的 Go 学习项目，构建一个可运行、可解释的微型数据库查询 planner。用户能输入受限的关系计划和统计信息，看到 egglog 探索出的等价计划、成本估计及最终选择。该项目与日常 Go 布尔条件检查器分离，避免将两种语义和规则混在同一命令中。

## 首版边界

- 输入为版本化 JSON：一棵计划树、关系 schema、基表行数、过滤与连接选择率。不解析 SQL。
- 计划节点只有 `Scan`、`Filter`、`Project`、`InnerJoin`。每个基表在一条查询中最多出现一次，列名带关系限定符。
- 过滤谓词限定为“限定列名 = 常量”；连接条件限定为两个限定列名相等。仅处理类型相容的等值条件。
- 逻辑语义为 bag semantics；过滤和投影应保留 SQL 风格的重复行数量。首版不实现 NULL、外连接、聚合、排序、LIMIT、相关子查询或真实查询执行。
- 重写至少覆盖：条件只引用单侧时下推到内连接输入，以及内连接交换和结合。连接重排不能丢失或错误附着连接条件；根输出列集合与顺序要维持。
- 从统计信息估计中间结果行数和代价，选中估算成本更低的候选；报告估算过程。没有统计信息或条件不合法时明确报错，不悄悄使用虚假的“最优”结果。
- egglog 用于等价计划探索。Go 端负责解析、schema/引用校验、统计信息、代价模型、计划输出及独立测试。必须验证 egglog 0.4.0 的提取能力；默认 AST 大小不等于数据库执行代价。

## 输入与输出示例

示例应表达：从 orders 和 customers 扫描，按 orders.status 过滤，然后按 orders.customer_id = customers.id 内连接，投影指定列。目录提供两表的行数与已知选择率。输出显示原计划、候选计划、每步估算行数和总成本，明确使用的是估算值。

JSON 字段的最终精确名称由接手智能体在第一项实现任务中定下并记录在 README；要求稳定、可版本化、无需嵌入未解析的 SQL 字符串来推断列引用。

## 正确性与成本约束

重写前后必须保持输入列身份、谓词绑定、根输出列顺序和重复行语义。可以用小型纯 Go 参考执行器或受控数据集测试规则语义；这些测试不能代替对所有 SQL 的形式证明。限制探索轮数、候选数量和进程时间，超过界限要给明确诊断。成本模型从简单的中间行数/连接代价开始，并在输出中标明假设；不要把估算成本描述为真实耗时。

## 构建方式

Go 1.26.2、官方 egglog CLI 0.4.0，优先支持当前 Windows PowerShell 环境。egglog 进程桥接可参考 `E:\Coding\egglog-helper\internal\engine\engine.go`，但不能直接依赖原项目的 `internal` 包。构建产物、Cargo 与 Go 缓存放入本项目的忽略目录。

## 完成标准

1. `go test ./...` 与 `go vet ./...` 通过。
2. 真实 egglog 参与端到端示例；至少一例选择下推、一例三表连接重排，并输出可核对的成本说明。
3. 输入非法、统计缺失、引擎失败、超时均明确报错。
4. 危险范围（NULL、外连接、重复关系名、未知列、谓词引用两侧却下推）得到拒绝或不适用结果，而非错误优化。
5. README 说明运行方式、假设及当前限制。
